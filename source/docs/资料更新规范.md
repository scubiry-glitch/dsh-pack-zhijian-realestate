# 专家资料月度更新规范（2026-08 建立）

## 一、目的
保持 32 位专家的知识库最新：每月检索其公开、正式言论 / 观点 / 资料，增量归档到各专家目录，使框架 A~E 的回答能反映专家最新立场，避免库 staleness 导致回答质量退化。

## 二、触发方式
- **手动触发（当前采用）**：用户每月发"更新专家资料""拍一下专家最新观点""更新专家库"等，Agent 当月执行。
- 不依赖会话内定时（session-only，会话结束即失效）；如需无人值守自动，需改用 WorkBuddy 本机自动化框架另行配置。
- 首月（2026-08）执行**全量基线**：回溯近 6–12 个月可检索的公开观点，建立基线快照；之后每月仅做**增量**（当月新增）。

## 三、目录与文件约定
- 每位专家：`专家材料/<专家名>/近期动态/`
- 月度增量：`近期动态/YYYY-MM_公开言论汇总.md`
- 首月基线：`近期动态/2026-08_基线快照.md`
- 总索引：`专家材料/_近期动态总索引.md`（按 月份 × 专家 列出各汇总文件链接 + "有无新增"标记）

## 四、检索方法
- 工具：WebSearch
- 每位专家检索式（1–2 次）：
  - `<专家名> 房地产 观点 2026`
  - `<专家名> 访谈 演讲 文章 最新`
- 覆盖渠道：署名文章 / 专栏、发布会 / 论坛演讲、主流媒体采访、官方可核验账号发声。
- 排除：营销软文、二手转述无出处、匿名 / 营销号内容、与房地产无关的泛财经闲谈。

## 五、单份汇总模板（YYYY-MM_公开言论汇总.md）
```
# <专家名>（BK-NNN）· <YYYY-MM> 公开言论汇总

> 检索日期：<执行日> ｜ 检索式：<用的关键词> ｜ 来源：公开网络

## 本期新增言论
### 1. <标题 / 主题>
- 时间：YYYY-MM-DD（或"2026年X月"）
- 场合 / 来源：<发布会 / 文章名 / 媒体>（附链接）
- 核心观点：<2–4 句提炼>
- 与既有 persona 关系：延续 / 强化 / 微调 / **观点变化提示**（偏离历史 bias 须标红说明）

### 2. ...

## 检索结论
- 本期新增 N 条；观点整体基调：<稳定 / 有变化>
- 待跟踪：<值得下月继续关注的信号>
```
（检索不到时：写明"本期未检索到该专家新增公开言论"，并附检索式备查，不编造内容。）

## 六、质量边界
- 只收公开、正式、可核验言论；保留原文链接与日期。
- **不修改**专家既有 persona / bias / Profile JSON——本规范是**增量更新**，非重写既有结构。
- 发现观点明显转向：在汇总中标"**观点变化提示**"，供后续框架调用时校准。
- 严禁编造：搜不到就写"未检索到"，绝补内容。

## 七、与框架的衔接
- 框架 E 自由提问时，若议题对口某专家且本月有新增，可内部参考其近期动态校准口吻与最新立场（仍不对外显来源）。
- 框架 A / B / C / D 涉及具体专家判断时同理。

## 八、执行步骤（Agent 用）
1. 确认月份（默认当前月；首月建基线，回溯近期）。**检索每位专家前，先读其 Profile（`专家材料/<专家名>/<专家名>_专家Profile_BK-NNN.json`）确认身份、主领域与立场，规避同名混淆（案例：海外瞭望员 BK-019 为广州中介协会体系，≠"武斌"等同名者）；再按确认后的身份检索**。
2. **仅用主会话逐一 WebSearch，禁用子 Agent / 多路并发检索**：2026-08 实测，子 Agent 4 路并发 WebSearch 触发平台频率限制（429，约每小时窗口重置），中断了 5 位专家；主会话单独串行检索额度正常、不受此限。故月度更新一律主会话分批串行，不并发。
3. 按模板写 `近期动态/...md`；无新增也写占位文件（含检索式与"未检索到"结论）。
4. 更新 `专家材料/_近期动态总索引.md`。
5. 向用户汇报：新增条数、有无观点变化、需关注项。

## 九、速率限制与并发禁令（2026-08-18 实测结论）
- **主会话 WebSearch 额度：正常可用**，月度更新全程走主会话即可。
- **子 Agent 多路并发 WebSearch：禁用**——曾触发平台频率限制 429（错误提示"使用量已超出频率限制，将在整点重置"），导致 5 位专家快照中断。
- 如不幸再撞 429：停止并发、等待窗口重置（通常整点）后继续主会话串行；已完成的专家不重跑。
- 用户已明确指令："别用子 agent"——本条为硬性约束，后续任何月度更新均不得重启子 Agent 并发检索。
