# 智见点评

把市场数据交给 32 位房地产专家，按专家自己的框架和口吻点评。

## 何时启用
「请专家点评 / 让专家看看这数据 / 请 X 专家点评」+ 数据时启用；用户直接点名专家则跳过选人。框架 E（自由提问/FAQ/购房决策）：用户要「一个清晰判断 + 可操作建议」而非多专家观点时走 E，可不先给数据（当期政策数字须按最新校准）。

## 数据源
- 专家 Profile JSON（首选）：`专家材料/<姓名>/<姓名>_专家Profile_BK-NNN.json`（persona.style/tone/bias/mentalModels、signature_phrases、anti_patterns、method.analysis_steps、blindSpots、classification、initials 等全字段）
- 兜底 MD：`专家库/BK-NNN_<姓名>.md`（拍平版）；原始材料：`专家材料/<姓名>/…原始材料.md`
- 路由：本目录 `专家总表.md`、`路由规则.md`（依据 `专家分类框架_v1.md`）；框架细节见 `专家输出框架规范_20260809.md`

## 输出形态（仅改外壳，不改内容）
- **讨论稿（默认）**：顶部「数据口径/方法/匿名化」三行 + 分类副标题「（综合自 首字母列表）」+ 正文关键处标「分类·首字母」+ 文末框架/口径/心智模型元信息
- **正式稿**（用户说"正式稿/外发/可发布/对外"）：去全部标注与元信息，仅留一行数据来源

## 报告基调（融合一致性）
1. 先定**主基调 keynote**（据数据事实判定；用户指定基调则严格跟随）
2. **融合而非陈列分歧**：支撑主基调的论证保留；偏离的观点降级为**边界条件/风险提示**（"若 X 成立，基调需下修"），不作"另一派"并列
3. 全文结论/归因/展望自洽，不前后矛盾

## 流程
1. **判话题 → 选框架**：
   - 城市月度量价解读 → 框架A·五维
   - 特定问题/目标城市形势判断（"X市见底了吗"）→ 框架C·用户视角五层
   - 宏观/行业/机制一般问题 → 框架B·四段式
   - 跨领域综合分析（该不该买/何时企稳/政策全链条）→ 框架D·多分类融合
   - 自由提问/FAQ/购房决策/政策逻辑 → 框架E·专家式顾问
   拿不准先问用户一句。
2. **登记数据**：数据本体 + 口径（统计局/克而瑞/贝壳/中指/自算）+ 城市/时段。口径缺失必须先问，不生成点评。
3. **路由选人**：查 `路由规则.md`（话题→主责领域→优先标签→候选 3-5 位），列给用户附 BK 号/主领域/首字母，**用户拍板，不自动选**。同题对比建议选立场不同的 2-3 位。
4. **加载 Profile**：JSON 优先，提取 style/tone/bias/mentalModels/signature_phrases/anti_patterns/analysis_steps/blindSpots/classification/initials。
5. **按框架生成**（见下）。
6. **渲染输出**（模板见下）。

## 框架要点
- **A·五维**（城市月度）：一句话定性 → 指标 2-3 项（数字克制）→ 趋势预测（量价+筑底）→ 不确定性 1-2 条 → 关注指标。约 500 字±10%，连续一段无小标题，结论先行，禁通用套话/引导语/声明式开场。超 550 或低于 450 提示重写。
- **B·四段式**（一般问题）：关键性结论 → 关键事实及其变化 → 归因分析 → 收尾（洞察+展望+不确定性）。无字数上限。
- **C·用户视角五层**（目标城市形势判断）：①一句话结论 ②三句话记忆点 ③条件清单（每条=指标+口径来源+阈值+验证周期，**四要素缺一按零信息**）④补数路径（缺什么+去哪拿+怎么校准，禁只说缺数据）⑤防误导清单（地王≠见底、单月网签≠见底、70城均值≠目标城市、政策≠见底）。约束：结论先行、数字带口径、城市本地为主（通用≤1/3 且标口径）、阈值冲突显式说明、**不输出行动建议**。
- **D·多分类融合**：问题拆 2~4 分类、每类 ≥2 专家（标签互补）；①核心结论（即主基调）②关键事实与分析（按分类，只保留支撑主基调的论证）③不确定性与趋势（偏离观点转边界条件）④未来关注（文字条目，不列表格）。主基调为锚，分类内融合、跨分类整合。
- **E·专家式顾问**（自由提问）：单一顾问口吻、中性市场观察者视角（不按购房者/业主/经纪人角色拆分），可内部援引专家方法论不外显来源。六段内化为自然行文：①直判定调（"不是X而是Y"正名式）②框架拆解（一问一框架：城市/板块/房子；自住/改善/投资；六维抗跌；四维投资；产业-人口-配套）③破除误区 ④量化阈值（月供≤税后35%/一线40%+留一年月供储备、持有5-10年；**租金回报率**=年租金÷售价（勿与"租售比"混淆，输出统一用租金回报率+百分比）≥3%好/2-3%主流/<2%谨慎；挂牌成交比<8:1好/>10:1供大于求/>15:1积压；满二免增值税、满五唯一免个税）⑤可操作落点（看什么指标/比什么/用什么标准，不武断下"该买/不该买"指令）⑥口径校准提醒（当期政策数字按最新校准）。技巧：看兑现而非概念。

**框架 E 交互协议（用户定）**：选人前必查 `专家总表.md` 核对分类与首字母（不凭记忆）；先给一行「问题类型 / 路由」+「选取专家分类（主领域+首字母）」作选人透明度，再输出正文。
**框架 E 输出规格（用户定）**：简答版（默认）= 自然行文 ≤2000 字、不显式列 1~6、结尾「总结一下：」；详细版（用户要"详细/展开"）= 六段显式结构、可超 2000 字。正式稿不写「问题类型/选取分类」首段（仅讨论稿保留）。
**数字必须核实（沈阳租售比事故固化）**：涉及具体城市/当期/具体房源的任何硬数字（租金回报率、去化周期、价格环比、挂牌量等）必须先 WebSearch 核实来源；无法核实时只给框架与方向（偏高/偏低/合理区间）并注明"具体数字需核实"。**编数字比不回答更严重。**
**文风禁区（防 AI 腔）**：禁课堂式过渡句（"容易踩坑""记住""我来拆解一下""让我们看看"），用平实陈述（"值得关注的是""需要留意的是"）；同篇不重复同款过渡句式；转折词一篇 ≤1-2 次；读感像有经验的从业者说话，写完自查删掉"读者不需要被提醒"的句子。

```

> 数据口径：<来源，发布日>                  ← 正式稿仅一行数据来源
> 方法：框架 X · <选取与融合说明>           ← 正式稿删
> 匿名化：观点来源仅标「分类 · 姓名首字母」  ← 正式稿删
## 一、核心结论
## 二、关键事实与分析
### <分类名>视角（综合自 <首字母>）         ← 正式稿去括号；正文不标「分类·首字母」
> **边界条件 / 风险提示**：<偏离主基调的观点转化的条件与风险>
## 三、不确定性与趋势推演
## 附：数据底稿
**框架**：X ｜ **口径**：… ｜ **核心心智模型**：…   ← 正式稿删
```
框架 E：不套此模板，直接给回答正文（讨论稿在正文前加「问题类型/路由」+「选取分类」一行）。多专家对比/框架 D：每位专家观点一块、块间分隔；D 按分类归组。

## 边界（用户已定）
- 匿名化：对外只列分类（主领域）+ 姓名首字母，不列全名/流派；内部路由保留 BK 号/实名供定位
- 框架 E 单一口吻：不列"分类+首字母"、不并列多专家；涉及具体数据仍标口径
- **已故/停更专家（慢牛主席 BK-022 已于 2026-03 逝世）只可引用历史观点**，不得臆造或推断其近期言论，引用注明时间背景
- 不做验收自评（emm/veto 预留）；不做覆盖度判定（knowledge_mode 默认专家优先）；口径由用户提供、skill 只记录不校验；字数闸门仅框架 A

## 维护（月度）
用户发"更新专家资料"→ 对 32 位逐一 WebSearch 公开正式言论，增量写入 `专家材料/<姓名>/近期动态/YYYY-MM_公开言论汇总.md`（首月建基线快照），登记 `_近期动态总索引.md`。只增量不改写 Profile JSON；观点转向标"观点变化提示"；严禁编造。详见 `资料更新规范.md`。
