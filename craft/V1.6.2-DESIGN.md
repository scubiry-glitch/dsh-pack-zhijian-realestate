# 1.6.2｜调度效率与文章质量

## 基线与目标

贵州租金与旅居 V5 试跑从建队到 15 项任务完成用时 182.4 分钟。候选观点阶段受同时活跃成员上限 2 影响；取证前有 20.5 分钟未开工；t9/t10 的发布故障拦住下游；正文台账与视觉评审的精确协议未随任务完整下发，已完成的内容反复尝试提交。以上窗口有交接、审核和真实修订，不能全当可节省时间。

1.6.2 的试跑目标是保留真实取证与独立复核，先消除协议猜测和无故等待；以单次 V5 全流程的阶段时间、失败次数、文章质量复核结果验证。不能仅以总时长缩短宣称质量改善。

## 本轮已开始的研发

1. 领域工艺明确逐章论证线索：每章从本次证据提出判断，写清比较基准、推理桥梁、竞争解释、剩余边界和读者决定。章数和小标题随材料变化。内容评审按实际章节审新增判断及反例。
2. 领域工艺把视觉评审的顶层字段、`pages` 对象结构和 Host 页图哈希算法写全。Host 的 V5 写作提示也明确 `calculation` 必须为非空字符串，并给出成功形态；校验错误指出类型及缺失字段。
3. V5 报告正文、图稿、来源台账和视觉审计仍须绑定冻结字节。任何格式提示或预校验不能代替证据真实性与独立评审。
4. 两份高质量参考的旧任务图已复盘于 `references/reference-quality-anatomy-v1.md`：成都案例证明“已有正文→开工前图文契约→并行渲染→独立校对”有用；角色案例证明“已有初稿→按视角独立找反例→有损失意识的融合→成文出图”有用。新报告要在创作阶段生成自己的章级判断和图稿，不复制旧页数、角色数与图型；任务输入须自动绑定真实上游任务和文件版本。
5. Host 已增加只读 writer 预校验入口 `node scripts/qa/v5-writer-preflight.mjs --team-root <团队目录> --artifacts <writer/artifacts目录>`；它和正式接受路径调用同一个 `collectV5WriterPreflight`，返回 JSON 错误列表，不发布材料、不变更 attempt。台账对象内部的来源、引用、计算和口径错误现在也可在一次检查中并列返回。
6. 调度器新增默认关闭的 `v5ResearchMaxActiveMembers` 选项。只在 V5 的独立候选观点或取证任务占满现有槽位且属于同阶段时，允许提高并发；普通任务、混合阶段和评审消息仍受原 `maxActiveMembers` 上限约束。队内出现 429/额度运行时阻塞后，新任务回退至普通上限，直到该阻塞按既有恢复流程解除。线上尚未启用或做 2 槽与 4 槽吞吐对照。
7. V5 成品评审的 `prepare_only` 现在返回 `visual_audit_template`：Host 直接从本次冻结 HTML/PDF 生成原字节哈希、页数和 72dpi 页图哈希；观察、结论、阻塞数和每页发现保持空白，由独立评审者填写。

## 接下来的 Host 实现

### P0：一个可执行的提交契约

- 将 writer、renderer 的 JSON Schema 与成功样例从实际校验器生成或作为同一份常量导出；冻结在任务输入中，避免文档与校验器再分叉。
- 继续把 writer、renderer 和视觉评审的可检查协议收敛到同一份校验定义；预校验不可发布材料、改变 attempt 或扣修订预算。
- 保持 Host 哈希模板与独立评审分工：审美、事实判断和实测发现只能由评审者填写。
- 校验失败分类记录 `protocol`、`content`、`external`；确定性格式错误不自动重试相同 payload。

### P1：研究阶段受控并发

- 当前全局上限 2 不直接提高。新增 V5 研究阶段的显式并发选项，候选观点与独立取证阶段可试 2→4，其他阶段沿用原上限；计划审阅时展示成本与供应商限制。
- 队列记录 ready、admitted、turn-start、first-tool、submitted、integrated 时间；等待原因区分 capacity、member busy、captain unavailable、输入漂移、外部服务。设置 429/额度触发的回退与冷却，不能靠循环重试抢槽。
- 上游完成后的可运行任务由持久化调度继续推进；队长暂时离线不应造成无界等待，但恢复不能越过用户选择、授权、独立评审和未知外部副作用边界。

### P1：减少重复取数，同时保留独立核验

- 研究前形成共享的原始数据快照与口径表，记采集时点、城市授权、序列窗口、指标定义和缺口。各专家用同一快照提出不同解释；独立复核者重算承重结论并抽查原来源。
- 允许表达策划在证据逐步返回时形成不冻结的草案。最终图稿和正文仍绑定全部已审输入，不能把草案当结论。

## 验收口径

- 无类型猜测：含对象形式 `calculation` 的测试在提交前指出“必须为非空字符串”；合法字符串通过。视觉审计缺 `finding` 或顶层六项任一字段时返回具体字段名。
- 每个实际分析章的论证线索可从 OUTLINE、正文、来源台账、图稿和内容评审记录贯通；评审至少核实一处最强竞争解释或明确说明本题无适用反例。
- 受控并发试跑分别记录 2 槽和 4 槽的完成时间、供应商 429/额度事件及恢复；若吞吐不升或失败增加，保持 2 槽。
- 统计排队、执行、工具等待、用户审批、协议返工、外部故障各自的耗时。总时长仅作结果指标，不从重叠窗口直接相加推导节省量。
