# 单套住宅租金定价｜取数说明与停走规则

供新场景 `t1` 使用。目标是一次生成可复核的证据包，交给 `t2` 填表；不在取数阶段先写价格结论。取数对象是**具体房屋**，因此先固定产品身份，再查可比。趋势和可比是两条链：趋势按**小区→商圈→城市**降级；同质可比按**同小区→商圈→区级补样**扩展，两者不能混写。

## 数据源与工具：谁负责什么

| 需要的数据 | 主数据源与调用工具 | 写进报告时的身份 | 无结果时的处理 |
|---|---|---|---|
| 标的真实形态、出租权限、装修、业主成本和最低可接受租金 | 房东/用户提供的房屋资料与现场核验；贝壳小区档案只辅助核区位及小区背景 | `业主输入` 或 `现场核验`；未核实项标“待核” | 产品形态不明就保留互斥分案；业主底线未确认就保持待确认 |
| 小区 ID、区位、商圈和当前在租房源 | **贝壳 CLI**：`beike rent resblock`、`beike rent detail -t resblock`、`beike rent search`、`beike rent detail -t rent_house`；`beike rent plate` 只辅助确认商圈 | **在租挂牌**，逐房源标抓取日、房源 ID、面积、产品形态及可租状态 | 同小区空则扩大至商圈同质，再到区级同质；不能把零召回写成零供给 |
| 真实成租价与去化天数 | 先试一次该环境有权限的**贝壳租赁行情** `beike rent market`；如用户另有签约/成交凭证，单独核实 | 有真实回执才标**成交观测** | `Unknown tool` 或无可核成交时留缺口；目标成交带仅能标**推断**，不能把挂牌价改称成交价 |
| 近 12 个月租金序列 | **政研通 CLI `zyt`**：`指标目录` 核定义，`地理树/地理搜索` 取真实 ID，`地理数据包` 取月度值；按小区→商圈→同城城市 | 标实际层级、指标键、单位、统计总体、观察期与末月 | 下一层级有可比序列才降级使用；三级均无值就展示缺口，不造图 |
| 分位数、三档定价、空置临界天数 | 本地确定性计算，从上述冻结回执及业主输入计算；结果放 `calculationSteps[]` | **计算/推断/建议**，不是第三方数据源 | 输入不足则该数值待确认，不沿用旧报告数字 |

本场景的单套月租主证据是**贝壳可比挂牌/可得成交＋业主标的事实**，时序背景来自**政研通**。Wind 宏观数据、售侧房价和网页泛搜不作为单套月租点估计的替代源。`beike rent market` 是否开放以本次真实调用为准；命令存在、`beike doctor` 正常，都不等于接口有数据权限。

### 凭据引用与备用 Key

领域包只保存凭据**标识**，不保存 Key 值。贝壳主凭据引用为 `BEIKE_MCP_API_KEY`（由宿主贝壳 CLI 的凭据机制提供）；政研通主凭据引用为 `ZYT_API_KEY`（由宿主政研通 CLI 的凭据机制提供）。备用凭据如已由运维配置，分别以 `BEIKE_MCP_API_KEY_BACKUP`、`ZYT_API_KEY_BACKUP` 标识，置于对应宿主的受控凭据存储中。实际启用前检查备用标识是否存在并有权限；不存在时记录“备用凭据未配置”，不可假装已切换。只有主凭据返回明确的认证失败且服务本身可达时，才在同一来源的备用凭据上重试**一次**；数据空、对象不存在、TopK 截断和工具不开放都不触发换 Key。回执只记录通道、主/备角色、错误码、切换时点与结果，不能记录 Key 值。两侧数据源不可互作凭据或行情替代。

## 0. 一页执行顺序

| 顺序 | 动作 | 拿到什么才往下走 | 没拿到怎么办 |
|---|---|---|---|
| 0 | 固定城市、小区、面积口径、户型、整租/合租、独立厨卫、出租权限、报告日 | `subject` 已知事实和未知项分列 | 影响产品形态的未知项建立互斥 A/B 案，分别取样 |
| 1 | `beike doctor`，政研通最小地理探针；保存通道状态 | 至少知道各通道是否可读 | 确定性故障只记一次，不让下游任务重复碰同一接口 |
| 2 | 贝壳小区消歧、房源查询；政研通同城地理搜索 | 两侧真实对象 ID、所属商圈、实体级别 | 名称冲突先消歧；禁止用贝壳 ID 猜政研通 ID |
| 3 | 同小区同形态、显式面积区间查询；逐条详情核验 | 回执证明实际命中产品和面积，留下可租有效行 | 零召回只记当前可检索挂牌缺口，扩至商圈同质样本 |
| 4 | 商圈及区级同质查询；TopK 超限时按租金段补全 | 每个独立样本池有回执、去重、剔除、有效 n | 无法取齐只写“可见样本”，不报全量分位 |
| 5 | 趋势按小区→商圈→城市取 `地理数据包` | 选中**第一个**同口径可用层级，保留前层失败原因 | 三层均不可得，记录缺口，不造图 |
| 6 | 冻结 `t1` 证据包 | 原始回执、查询账、可比逐行表、趋势序列/缺口、SHA256 | 缺任一承重证据则 `t2` 对应价格字段保持待确认 |

## 1. 只做一次的通道和对象检查

下列命令是**参数模板**，城市与小区必须替换成当前标的。原始 stdout、stderr、退出码和运行时间一起保存；不要只留 AI 摘要。贝壳 `--json` 的外层通常是 `{ "ok": ..., "data": "..." }`，`data` 仍可能是中文检索回执文本，不能假定它已是逐房源 JSON 表。

```bash
beike --version
beike doctor
beike rent resblock -c "$RENT_CITY" -q "$RENT_COMMUNITY" --json > raw/beike-resblock.json
beike rent detail -c "$RENT_CITY" -t resblock -i "$BEIKE_RESBLOCK_ID" --json > raw/beike-resblock-detail.json
zyt --json 地理树 --城市 "$RENT_CITY" > raw/zyt-geo-tree.json
zyt --json 地理搜索 --城市 "$RENT_CITY" --关键词 "$RENT_COMMUNITY" > raw/zyt-community-search.json
```

- 贝壳回执核小区全名、城市/城区/商圈及小区 ID；近名小区、同名不同区不得合并。用 `resblock` 返回的 ID 才能调贝壳小区详情。
- 政研通地理搜索核 `geo_id`、`level`、`parent_id`、`city_id`；`level` 必须与想取的层级一致。地理树 `counts` 若显示某城社区/商圈节点为 0，整批报告可据此记该层无覆盖并停止对每个标的重复搜索，但先用一次目标搜索核实目录状态。
- `beike doctor` 全绿不代表租赁行情工具开放。已见 `rent_market_search` 返回 `Unknown tool`；记录一次后转可用的房源检索，不重复重试，也不能从挂牌样本推成租价。

## 2. 贝壳同质可比：先精准，再扩圈

先查同小区当前挂牌，再查“户型＋整租/合租＋**显式面积上下界**”。面积写“35 平”曾在不同回执中被解析成 `=35` 或一个区间，因此用“32到38平”这类明确上下界，并以返回的**实际命中检索条件**为准。

```bash
beike rent search -c "$RENT_CITY" -q "$RENT_COMMUNITY 在租房源" --json > raw/community-all.json
beike rent search -c "$RENT_CITY" -q "$RENT_COMMUNITY 一居室 整租 32到38平" --json > raw/community-same-product.json
beike rent search -c "$RENT_CITY" -q "$RENT_BIZCIRCLE 一居室 整租 32到38平" --json > raw/bizcircle-same-product.json
beike rent search -c "$RENT_CITY" -q "$RENT_DISTRICT 一居室 整租 32到38平" --json > raw/district-same-product.json
beike rent detail -c "$RENT_CITY" -i "$RENT_LISTING_ID" --json > raw/listing-detail.json
```

上面的“一居室、整租、32到38平”只是**形状示例**，实际查询须替换为已核标的口径。每次从回执抄出：`查询问题`、`本次实际命中的检索条件`（含 `match_type`）、总召回、展示 TopK、房源 ID、取数时间。文字里有“普租、面积、户型”而实际过滤没命中时，逐行用返回字段复筛，并记剔除理由。详情与列表状态冲突时以可核详情复查；“不可租”、产品形态不符、面积口径不明的行不得直接计入有效样本。

同小区零召回 ≠ 小区历史无该户型，也不说明工具故障；同城其他对象或商圈的阳性回执可区分覆盖与通道问题。跨区域补样仍须保持产品形态、面积口径、时间接近；跨小区异质性进入限制说明。

### TopK 截断怎么处理

1. 若 `totalRecall <= 展示数`，逐行核可租状态后，才可能称本查询完整展示。
2. 若 `totalRecall > TopK`，优先在**同一产品、地域、面积条件**下加互不重叠的月租区间，例如 `月租金2000到2499元`。每段核返回的 `租金 between [下限,上限]` 确实命中；未命中就不能当租金段补取。
3. 某段仍截断时继续细分；用房源 ID 去重，核叶段总召回之和、去重后 ID 数与根查询总召回是否一致。端点重叠要明确去重；分段不同时间抓取不能叫严格同一时点快照。
4. 无法覆盖全价格域、字段不足或总数不一致时停止“取齐”宣称，只统计可见且有效的行。这样仍能做有限样本观察，但不能报“市场全量 P25/中位”。

已验证的贝壳租金段查询形状为 `... 一居室 整租 32到38平 月租金2000到2499元`；是否有效仍以**本次**回执的实际过滤为准。不要把板块单次 Top 10、区级 Top 10 和分段并集混成同一个样本池。

## 3. 近 12 个月趋势：小区→商圈→城市

先看 `zyt --json 指标目录` 对应租金指标的名称、定义、单位与覆盖；同一张图只用同指标、同单位、同统计总体。主路径用真实地理 ID 取 `地理数据包`，不要直接把贝壳 ID 填给政研通。

```bash
zyt --json 指标目录 > raw/zyt-indicator-catalog.json
zyt --json 地理数据包 --城市 "$RENT_CITY" --地理编码 "$ZYT_COMMUNITY_GEO_ID" > raw/trend-community.json
zyt --json 地理搜索 --城市 "$RENT_CITY" --关键词 "$RENT_BIZCIRCLE" > raw/zyt-bizcircle-search.json
zyt --json 地理数据包 --城市 "$RENT_CITY" --地理编码 "$ZYT_BIZCIRCLE_GEO_ID" > raw/trend-bizcircle.json
zyt --json 地理数据包 --城市 "$RENT_CITY" --地理编码 "$ZYT_CITY_GEO_ID" > raw/trend-city.json
```

以上按顺序**有条件执行**：小区可用便停止；小区不可得才查商圈；商圈不可得才查城市。城市 ID 从地理树根节点取得。选中的 `scopes[geoId].level` 与 `indicator` 对象、`periods` 和 `values` 必须核对；`rentIdx`、`RENT_PRICE`、`keRentIdx` 等不能凭名字或数值大小视为同一口径。已见“指标时序”的城市 `rentIdx` 返回空，而城市 `地理数据包` 含 `rentIdx`；前者为空时不要直接判定该城全无趋势。

可用定义：真实目标地理对象；指标定义与单位可核；最近可得的 12 个日历月可排成序列，至少有足够观测点供呈现；基准日之后的月份不得纳入。缺月保留 `null`，图上断线；序列滞后写真实末月和滞后月数。商圈/城市级跨户型序列只能说明市场时点背景，图题必须写“商圈/城市”，不得写“小区趋势”或据此直接定单套租金。

`fallbackAttempts[]` 逐级记录 `level/name/geoId/indicatorKey/status/reason/receiptPath`。状态至少区分：对象未找到、指标无值、口径不合、月份不足、权限/接口失败、已选中。三级无可用序列时 `trend.status=unavailable`、`selectedLevel=null`，报告显示缺口卡。

## 4. 证据包交给下一任务的最小结构

`t1` 一次性交付 `raw/` 原始回执、`queryAudit[]`、`comparablePools[]`、`comparables[]`、`trend.fallbackAttempts[]` 和真实月序列/缺口，及每个回执的 SHA256。价格和趋势来源分别标“挂牌/成交/模型”“小区/商圈/城市”；统计池保留原始行、重复、排除、有效 n 的倒推。`t2` 只从这份冻结证据包测算；需要补数时明确补哪个缺口，不再从头广搜。

## 5. 已知弯路及单次止损

| 已见问题 | 一次处理动作 |
|---|---|
| `rent_market_search` 返回 `Unknown tool` | 记录行情通道不可用；继续租赁挂牌检索，成租价与去化天数留缺口。 |
| 查询写“35 平”，实际面积过滤变成精确 35㎡ 或意外放宽 | 改用显式上下界，并核回执的实际过滤；不得沿用旧查询的样本 n。 |
| 总召回大于 TopK | 同口径价格分段，核实际租金过滤与并集；取不齐即限于可见样本。 |
| 检索命中房源，详情显示“不可租” | 剔除或核查，不计有效在租样本。 |
| 政研通地理搜索空或地理树无社区/商圈节点 | 记当前层级不可得；按顺序降级，城市包再试一次。 |
| `指标时序` 空但地理包有值 | 以核实的地理包和指标定义判断，分别留两份回执，不把空序列当 0。 |
| 最新趋势月早于报告月 | 图上写真实观察期和滞后；只作历史背景。 |
