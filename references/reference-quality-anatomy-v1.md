# 两份报告参考的内容与图稿质量复盘（1.6.2）

本页供 V5 的 writer、renderer、reviewer 共读。两份完整 HTML 分别是 [成都数据集团合作报告](zhijian-designer-v1.html) 和 [角色重写报告](zhijian-credit-policy-v1.html)，与服务器对应文件逐字节一致。它们是**表达方法参考**，其中业务事实、数据、判断、章数、图数和配色都不能作为新报告的证据或固定模板。

## 成都合作报告：把信息变成合作决策

报告从“是否合作、先做什么、何时承担更大风险”出发，卷首先给出三层判断：合作有结构性基础；成本优势有前提；宜分层推进。后文按资源互补→成本机制→资质价值→合作层次→方案比较→风险和行动推进，而非按收集到的材料来源罗列。每一节回答上节留下的决策问题。

关键论证不是列数字，而是**事实→机制→边界→动作**：2.7 节先把 token 单价拆成折旧、电力、机房、运维、利用率和渠道加价，再把六项成本来源挂到相应环节、标确定性；随后列出补贴退坡、绿电直供未放开、未投运、缺 SLA 等限制，最后把“便宜”收束成“先用作谈判杠杆，不能立即形成供货依赖”。4.2 节用挂牌案例质疑静态资质溢价，6.3—6.4 节再用方案比较、不同性质的价格锚和验证顺序回答“现在签什么”。价格锚明确区分实付、口头意向与情景测算。

图跟着论证关系选型：双方“握有/缺乏”用双向交换；可信空间用输入→加工→产品→服务；成本用公式链＋来源挂注；纯采购与股权用平行路径解耦；四方案用矩阵；折扣与行动用锚点＋时序。图注反复说明“定性示意”、原文出处和未验证条件。图是观点的短路径，不是把相同数字换成卡片。

## 角色重写报告：一个总命题贯穿多主体

总论把“预售的隐性融资功能显性化、风险归属转向项目”作为统领命题，再让每类主体回答同一组**有内容的不同问题**：旧身份是什么、条款怎样改变权责、谁得利/付费、证据与计算支持什么、何种条件会让推断失效。十三个分析章分别落到买方、银行、开发商等，不把角色名单当观点。结尾横向重组为知情权、控制权、责任三项再分配，并给出可证伪的预言和失灵变量，避免“十三个孤立小结”。新任务应从自己的材料找统领命题和分组逻辑，不照搬角色数或五件套。

图表把**结果和代价同屏**：购房者章的 30/40 年测算同时给出月供下降与总利息上升，银行章展示降息静态冲击和对冲后的净影响，租赁运营章把开发→收储→运营→退出和“回报率约 2% / 资金成本约 3%”两道闸门放在一图。机制、权责、路径用定性结构图；连续序列、城市差异、概率区间才使用有刻度的量化图。标题尽量说判断，图内用有限颜色区分存续、警示、待验证，图下注明数据日期、口径、测算或研判身份。十三个分析章各有一张点睛图，另有总论与总结图，形成持续的阅读节奏。

## 对 V5 的可执行转译

1. **先写论证再定目录。** 每个承重章记录读者问题、本次证据带来的新判断、原始事实与口径、比较/计算/机制桥梁、最强替代解释、失效条件、对决策的影响。内容不足则合并章或退回取证，不为模板凑章。
2. **图稿先有观点句。** `figure-plan.json` 中的 `claim` 应是读完图应记住的判断，`relation` 应写出比较、流向、因果环节、约束或时序；`encoding` 由关系决定。`sourceQuote` 和 `sourceClaimIds` 绑定本次正文与来源，`decision` 写图怎样改变读者判断。图的颜色、长度、箭头各须有语义。
3. **做双向复核。** 从正文反查图是否兑现关键逻辑，从图反查正文/台账是否支持每个标签和数值。独立评审遮住标题时应能复述关系，读完标题后应能说出图增加了什么；若去掉图不损失理解，应重画或删掉，不能以卡片数量充数。
4. **按证据状态画图。** 实测、官方统计、用户给定条件、口头报价、情景测算、推断分别标识；缺失数据留空，不能画成零。不同时间和口径的比较需显著注明限制；不同单位不可共用一条暗示可直接比较的刻度。定性箭头不得冒充已证实因果。
5. **分开验收章与页。** 这两个参考示范了“每个分析章有图”，但未示范“每个物理页有图”：成都报告 13 页、11 个 `.fig`；角色报告 13 个分析章各有图，PDF 为 24 页，若干页无图。若交付规格要求逐页有图，应在最终 PDF 逐页检查，而不能用逐章计数替代。

## 回看当时的任务图与提示词

**成都合作报告的任务图主要负责渲染已有正文。** 留存的团队任务为 t1 架构审定 → t2/t3/t4 分段并行渲染 → t5 独立口径校对 → t6 组装与页面检查；内容唯一源是已经写好的八章 Markdown，当前参考 HTML 是此流程后又修订的 v2。不能从渲染任务的成功反推这张图生成了正文的论证质量。可取的是开工前的 `spec.md`：逐页标明承载章节、每图所表达的关系、可入图的准确数字与不确定性标签；t1 先查容量、图型与来源；t5 反向扫描图文新增数字，G1 核存疑措辞、G2 核数字，最后用浏览器查遮挡。p02 重复导语、p05 漏标注等实质问题在独立校对后修复。新任务应保留“冻结正文与图稿接口→分工执行→独立核对”的依赖关系，页数和具体图型须由本次材料决定，不能照搬其 13 页表格。逐 token 命中也不能代替语义、计算与来源核验。

**角色重写的任务图主要负责批判已有 v4 并生成 v5.1。** t1–t5 五位专家独立评审同一份 v4，队长在各自消息里补上不同视角：行业经营、存量转型、政策条款、宏观测算、批判证伪；t6 在全部完成后融合，t7 才渲染。通用提示要求各人判断最坚实/最脆弱论点、补强缺口、给可证伪预言的验证锚并排序失灵条件。价值不在“五人”数量，而在**各自提出可检查的异议**：存量视角补时点和经营约束，宏观视角复算并补银行端对价，批判视角找被忽略的受害者与过度类比，融合稿据此把一些绝对化结论缩窄。第二轮深化以消息追加，说明真实的反驳与修订不能只靠一次任务提交。v5.4 的每章五件套和十三条【点睛图】描述已写在后续 Markdown 正文里；存档的 t1–t7 图只能证明 v4→v5.1 的路径，不能证明它独立产出了 v5.4。旧 t7 提示甚至把融合稿误称为“t2”，队长后来另发消息指定最终源文件；这种文字与任务依赖不一致应由 Host 的任务输入自动绑定避免。旧 t7 的内部质量分为 39，不能仅凭任务完成状态宣称成品视觉通过。

**新流程的提炼。** ①先让作者按本次证据提出统领命题与章级论证线索，再安排明确分工的独立反驳；②融合时保留强反例、条件与少数意见的证据，不应把所有异议机械降格成脚注（旧融合提示的“偏离观点降级”有此风险）；③正文底稿同步写每张图的观点、关系、要用的数值/原句与口径，交接给渲染者，但正文中不写技能调用；④冻结已审正文和图稿的原字节，任务输入由系统给出真实上游任务与文件绑定，渲染者不得凭旧消息猜版本；⑤独立检查分别覆盖内容推理、来源计算、图形语义、最终物理页，不把格式门禁或自动评分当质量结论。

## 不能照抄的地方

- 成都参考用固定 794px 页面；在 375px 视口实测产生横向溢出。V5 仍需响应式屏幕和独立 A4 排版。
- 角色参考把月供、总利息、可贷本金放在同一卡片，读者可能误以为六条共享可比刻度；新图宜按单位分组并明确各自基线。京宁对照图含不同截止月份，必须把时间差放在图面显著位置，不能只藏在脚注。
- 两篇的来源说明与口径标签提高可追溯性，但“写了来源”和“论断已核实”不同。角色报告的概率为研判，不是统计频率；成都报告的口头报价不是已履约价格。新报告仍须使用本次原始来源、回执、计算和独立复核。
